## Для основной сущности реализовано
1. Создание записи
Спектакли -> Выбор -> Оплата сейчас или позже
2. Вывод всех записей.
Билеты
3. Получение записи по ID.
Билеты -> Получение билета
4. Изменение записи
Билеты -> Получение билета -> Изменение
5. Удаление записи.
Билеты -> Получение билета -> Удаление
6. Поиск записей.
Билеты -> По названию
7. Фильтрацию записей.
По статусу, по статусу спектакля.
8. Сортировку записей.
По статусу, по дате спектакля.

## Бизнес-правила

1. Нельзя забронировать билет без данных пользователя.
2. Нельзя забронировать занятое место.
3. Нельзя купить отменённый билет.
4. Нельзя отменить уже отменённый билет.
5. Нельзя забронировать места, которого нет в зале.


## БД
### Performance
```
id: serial PK
title: VARCHAR(255)
description: text
performance_date: TIMESTAMPTZ NOT NULL
duration: int
base_price: NUMERIC(10,2)
```

### Ticket
```
id: serial PK
user_id: int FK
performance_id: int FK 
row_number: int CHECK (row_number > 0 AND row_number < 15)
seat_number: int СHECK (seat_numbe => 0 AND seat_numbe <= 20)
status: ENUM ("booked", "paid", "canceled") DEFAULT "booked"
created_at: TIMESTAPTZ DEFAULT now()

CREATE UNIQUE INDEX tickets_active_seat_uniq
    ON tickets (performance_id, row_number, seat_number)
    WHERE status IN ('booked', 'paid');
```
